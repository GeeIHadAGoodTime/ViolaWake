## Notable findings during the run

- **Frontend was previously broken at signup** because the deployed bundle had `/api` (same-origin) baked in. Cloudflare Pages doesn't proxy `/api/*` anywhere, so register POSTs would 405 from the live site. Fixed during this run by passing `VITE_API_URL=https://api.violawake.com/api` to the build. **This needs to be the standing convention for every frontend rebuild** — see `docs/DEPLOYMENT.md`.
- **`pip install violawake[oww]` does NOT yield a working detector out of the box.** The user must additionally run `python -c "from openwakeword.utils import download_models; download_models()"` to fetch the OpenWakeWord backbone ONNX files (the openwakeword PyPI wheel doesn't bundle them). The README's quickstart should call this out.
- **`openwakeword` upstream changed its backbone files** since the SDK was published; SDK warns `OWW backbone hash mismatch: expected 70d164290c1d095d, got e8444299a314fbb2`. Inference still runs, but accuracy on real "Viola" speech could differ from training. Track in `docs/PRODUCTION_STATUS.md`.
